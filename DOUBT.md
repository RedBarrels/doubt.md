# DOUBT.md

A ruthless self-interrogation framework for engineering projects. Before you write code, spend tokens, or burn a weekend — run your idea through these gates.

## The Gates

Every idea must survive all 7 gates. If it fails one, it's not necessarily dead — but you must document WHY you're proceeding anyway.

| # | Gate | File | Core Question |
|---|------|------|---------------|
| 1 | [[01-does-it-exist]] | Originality | Am I reinventing the wheel? |
| 2 | [[02-is-it-needed]] | Necessity | Does anyone actually need this? |
| 3 | [[03-is-it-effective]] | Effectiveness | Will it actually solve the problem? |
| 4 | [[04-is-it-sound]] | Engineering | Is the approach technically sound? |
| 5 | [[05-is-it-secure]] | Security | Will this get hacked in minutes? |
| 6 | [[06-is-the-cost-right]] | Cost | Am I burning money/tokens for nothing? |
| 7 | [[07-is-this-the-way]] | Approach | Does it HAVE to be done this way? |

## How To Use

1. Copy `templates/DOUBT-SESSION.md` into a new file named after your project
2. Answer every question honestly — if you can't answer, that's a red flag
3. Score each gate: PASS / CONDITIONAL / FAIL
4. If 2+ gates FAIL, stop and rethink
5. If any gate is CONDITIONAL, document the condition and set a review date

## Philosophy

This is not about killing ideas. It's about killing *bad execution* of good ideas, and killing *good execution* of bad ideas. The worst outcome is building something polished that nobody needs, or building something needed but so poorly that it collapses.

> "The first principle is that you must not fool yourself — and you are the easiest person to fool." — Feynman
